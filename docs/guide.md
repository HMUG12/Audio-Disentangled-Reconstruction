# 使用指南

这篇文档面向已经装好 ADR Studio、准备真正开始用的人。按顺序读完，你就能完成「登录 → 选控制台 → 建音色 → 训练 → 合成 → 对外调用 → 备份」的完整闭环。

> 只想尽快听到声音？先看 [快速开始](README.md)，再回来补细节。

---

## 1. 首次启动与登录

### 1.1 安装之后发生什么

Windows 安装包分 **CPU 版** 和 **GPU（CUDA）版**，两者共用同一个 AppId，可以原地覆盖升级，已经下载的底模和声音档案都会保留。

第一次双击启动时，依次会看到：

1. **使用条款页** —— 必须点击「同意」才能继续。不同意时服务进程会拒绝启动。
2. **首启配置向导（3 步）** —— 账号、设备与性能、存放位置与隐私。不想逐项设置可以点「全部用默认」。
3. **预热页** —— 自动下载预训练底模（约 2GB），并加载引擎。页面会显示下载进度和当前阶段；**底模下载 + 引擎加载完成后才会进入启动器**。
4. **启动器** —— 三个控制台卡片、模型入口、设置和关于页。

预热只发生在第一次（以及底模缺失时）。之后 ADR 完全离线运行，不再需要网络。

### 1.2 本机账号

桌面版的账号是**只属于这台电脑的本地账号**，不联网、不注册、不上传：

- 默认账号：`ADR`
- 默认密码：`Adr12345@`

首启向导里可以改；之后在「启动器 → 设置 → 本地账号」里修改用户名和密码（密码至少 6 位）。口令只以 PBKDF2 派生值保存在数据目录的 `.local_account` 中，明文不落盘。

登录在预热页首屏完成。它只用于解锁本机界面，和任何云端账号无关。忘记密码时，删除数据目录下的 `.local_account` 会回到首次登录状态（声音档案不受影响）。

> 源码方式启动、`server.bat`、Docker 形态没有这个登录页，它们直接以 HTTP API 对外服务。

### 1.3 条款同意的其他方式

| 形态 | 同意方式 |
| --- | --- |
| 桌面版 | 首次启动在条款页点击「同意」 |
| 命令行 / 源码 | 启动参数加 `--agree-terms` |
| 服务端 / Docker | 环境变量 `ADR_AGREE_TERMS=1` |

未同意时服务进程会以退出码 2 结束。同意记录只写本地数据目录。

## 2. 三个控制台怎么选

启动器里是三个入口，能力同源、数据互通，只是操作颗粒度不同：

| 控制台 | 地址 | 适合谁 | 主要能力 |
| --- | --- | --- | --- |
| **新手控制台** | `/easy` | 第一次用、只想快速出声 | 选声音 → 打字 → 听效果，三步；零参数 |
| **专业控制台** | `/pro` | 要训练、调参、看曲线、管模型 | 总览、声音克隆、语音合成、模型库 |
| **调用控制台** | `/call` | 要把 ADR 接到别的软件 | 双端点调试、参数说明、生成 cURL / Python / JS 代码、N.E.K.O 配置对照 |

怎么选：

- **只想让文字开口**：新手控制台。它默认用已就绪的引擎，第一次合成会等冷启动，之后是秒级。
- **想训练自己的音色、控制轮数 / 显存配方 / 语速 / 切句**：专业控制台。
- **已经会用，准备接 N.E.K.O 或自己的程序**：调用控制台。
- 三个页面右上角都有「文档」按钮，随时可以打开文档中心；语言和主题切换也在顶栏。

索引页（`/`）只是入口，不参与合成。

## 3. 音色档案（Profile）

音色档案是 ADR 的一等公民。一个档案 = 一段参考音频 + 一份元数据 +（可选）微调权重。

### 3.1 档案里有什么

```
data/voices/<档案名>/
  ref.wav     参考音频（干净、单说话人、建议 3–10 秒；建档录音 1 分钟以上更好）
  meta.json   prompt_text / t2s_weights / vits_weights / style / created_at 等
```

- 合成的「像不像」主要取决于 `ref.wav` 和微调权重。
- `meta.json` 里的权重路径可以指向 ADR 自己训出来的产物，也可以指向你手工放进来的 GPT-SoVITS 权重。
- 档案名就是 `data/voices/` 下的目录名，也是调用时 OpenAI / N.E.K.O 侧看到的模型 ID。

### 3.2 新建档案（录制或导入）

在 **新手控制台** 第一步点「创建新声音」，或在 **专业控制台 → 语音合成** 里导入档案包：

1. 准备一段录音：**一个人说话、环境安静、没有背景音乐**。支持 `wav / mp3 / flac / m4a / ogg`。一分钟以上效果最好，几秒钟也能建出可用的初始档案。
2. 选择「这段录音说的是什么语言」（中文 / English / 日本語 / 한국어 / 粤语）。这个标记会决定该档案后续合成时的默认语言。
3. 起一个名字（最多 20 个字符，不能和已有档案重名）。
4. 点「开始学习这个声音」。后台会做切片、转写、特征提取并建档；页面显示进度，失败会给出原因和重试按钮。

档案建好后会出现在声音列表里，可以直接合成。此时是**零样本**效果；想更像，继续训练。

### 3.3 给档案绑定训练权重

有三条路径，效果一样：

- **新手控制台**：选中已有声音 → 创建新声音 → 勾选「改进已有声音」→ 上传新录音。它会以旧权重为起点续训，训完自动版本化绑回同一档案；旧版本保留，效果变差可以回滚。
- **专业控制台 → 声音克隆**：填写「训练后绑定到音色档案」，训练完成后自动绑定。
- **手动**：训练产物在 `output/` 下，在档案元数据里指定 `t2s_weights` / `vits_weights`。

### 3.4 导入 / 导出 / 回滚

- **导出音色包**：新手控制台或专业控制台都有「导出档案包」，生成 `.adrvoice` 文件（参考音频 + 绑定权重 + 元数据）。用于备份或换电脑。
- **导入音色包**：选择 `.adrvoice` 或 `.zip`。同名档案会询问是否覆盖；如果包里的权重正被其他档案共用，会二次确认后才继续。
- **回滚上一版**：专业控制台「↩ 回滚上一版」把档案恢复到上一版微调权重，当前版本自动入历史，可以逐版回退。
- 档案包里有声音模型，**只发给你信任的人**。

## 4. 训练

训练入口在 **专业控制台 → 声音克隆**。

### 4.1 开始前

- 训练**硬依赖 NVIDIA CUDA**。AMD / Intel 显卡和纯 CPU 可以推理，但不能训练；可以在别的 NVIDIA 机器或云 GPU 上训完，再把音色包拷回来。
- 显存 4GB 起可训，8GB 更从容。其它占用显卡的程序（游戏、浏览器硬件加速、另一个 TTS 服务）先关掉。
- 准备一段干净录音，上传后引擎会自动切片和转写。

### 4.2 参数怎么填

| 参数 | 说明 |
| --- | --- |
| 实验名称 | 本次训练的标识，也用于产物目录名 |
| 训练轮数 | 1–50，默认 8。数据少时轮数不是越多越好 |
| 显存配方 | `8GB+`（batch 4，速度快）或 `4GB`（batch 1，单段 ≤10 秒） |
| 训练后绑定 | 自动建档绑定（推荐）/ 不绑定 / 绑定到已有档案 |
| 质量门禁 | 默认开启，相似度 ≥ 0.80 自动早停，避免过拟合 |

### 4.3 过程中看什么

- **状态 / 最佳相似度 / 零样本基线**：判断这次训练有没有真的超过「不训练」的效果。
- **相似度曲线**：每轮门禁打分，绿色目标线是 0.80。
- **训练日志**：实时滚动，失败原因通常直接可读。

点「■ 停止」会同时停掉训练和质量门禁。训练结束后产物在 `output/` 下，日志在数据目录的 `logs/` 里。

### 4.4 训练失败的常见原因

显存不足、数据太短 / 全是静音、磁盘空间不足、同时开了两轮训练（会返回 409）、缺少训练脚本（安装包不完整）。具体处理见 [故障排查](troubleshooting.md)。

## 5. 合成

### 5.1 专业控制台

专业控制台 → 语音合成：

1. 选择音色档案（可刷新、导出、导入、回滚）。
2. 输入文本。
3. 常用参数：语速 `0.5–2.0`、随机种子（`-1` 表示每次随机）、音频格式 `wav / mp3 / raw`。
4. 展开「高级参数」可以改：文本语言、参考音频语言、切句方式（`cut0` 不切 / `cut1` 凑四句 / `cut3` 按句号 / `cut5` 按标点）、`top_k` 等采样参数。
5. 点「✦ 开始合成」，等待结果；可以试听和下载。

第一次合成需要加载权重，可能要几十秒；之后常驻内存。合成请求在引擎内部串行排队，界面显示排队和合成状态。

### 5.2 新手控制台

选声音 → 打字（可选「说什么语言」，默认自动识别，中英混合也没问题）→ 生成 → 播放 / 保存。它把专业参数都收起来了，适合日常使用。

### 5.3 声音不像 / 没声音

- 先确认参考音频干净、只有一个人、没有音乐。
- 确认档案是不是真的绑定了训练权重（专业控制台训练页会显示相似度）。
- 文本不要全是标点或空白。
- 其它排查见 [故障排查](troubleshooting.md)。

## 6. 调用台与外部接入

### 6.1 服务默认在哪

默认只监听 `127.0.0.1:9881`，本机可达。需要局域网其它设备调用时，必须**同时**做两件事：

```powershell
$env:ADR_TTS_API_KEY = "<你的密钥>"     # 支持逗号分隔多把
python -m adr.server --addr 0.0.0.0
```

否则任何能连上端口的设备都可以无鉴权调用。

### 6.2 兼容面

| 接口 | 用途 |
| --- | --- |
| `POST /api/v3/tts/stream-input` | GPT-SoVITS api_v3 双工流式合成 |
| `GET /api/v3/voices` | 音色列表（即 ADR 声音档案） |
| `POST /v1/audio/speech` | OpenAI 兼容 TTS |
| `GET /v1/models` | OpenAI 兼容模型列表（即音色档案） |
| `POST /api/v2/tts` | GSV api_v2 兼容（N.E.K.O 默认走这里） |
| `POST /api/adr/v1/tts` | ADR 原生接口，按档案名合成 |
| `GET /api/adr/v1/health` | 健康检查（引擎阶段 / 就绪状态） |

完整字段、错误码和流式字节格式见 [TTS API 规范](tts-api-spec.md)。

### 6.3 调用控制台怎么用

- 顶部切换「原生 `/api/adr/v1/tts`」或「GSV 兼容 `/api/v2/tts`」。
- 左侧填参数，右侧实时生成 cURL / Python / JS 代码，可以直接复制。
- 「合成试听」会用当前参数真的请求一次本机服务，方便对照响应耗时和音频。
- 下方的 N.E.K.O 配置对照表会同步当前档案名，按表填即可。

### 6.4 N.E.K.O 最短路径

1. 启动 ADR（桌面版或 `python -m adr.server`），确认横幅显示端口 9881。
2. N.E.K.O → 语音合成 → 服务商选 **GPT-SoVITS**（或 OpenAI 兼容）。
3. 地址填 `http://127.0.0.1:9881`。
4. 刷新音色列表，ADR 的声音档案会自动出现。

首次合成有冷启动，之后是流式秒级响应。

## 7. 设置：全局默认值 vs 临时值

这两个概念经常被混淆，区别只看一件事：**改完之后，是下一次启动仍然有效，还是只对当前这一次请求有效。**

### 7.1 全局默认值（启动器 → 设置）

桌面版设置里的改动会以**进程环境变量**注入本地引擎，不修改系统环境变量；点「保存」后，**下次启动引擎时生效**。

| 设置项 | 作用 |
| --- | --- |
| 对外提供调用（局域网） | 引擎监听地址与鉴权联动 |
| API Key | 多把逗号分隔；留空 = 不鉴权 |
| 声音档案存放目录 | 对应 `ADR_DATA_DIR`；改目录不会自动搬旧档案 |
| 默认声音档案 | 对应 `ADR_TTS_DEFAULT_PROFILE`；请求未指定档案时回退使用 |
| 模型下载源 | HuggingFace 官方 / hf-mirror 国内镜像 |
| 开机自启、下载限速 | 壳行为与底模下载 |
| 声音安全审计日志、WAV 标注 AI 生成 | 只记事件、不写文本与声纹 |
| 高级：服务端口、NUMBA 缓存目录、推理设备、CPU 线程、日志级别、数据加载进程数、CUDA Graph、CPU 兼容模式 | 排障与性能开关 |

这些值是**所有控制台、所有请求共享的默认值**。比如把「默认声音档案」设为 `my_voice`，那么调用方不带 `profile` 时就用它。

### 7.2 临时值（控制台里的参数）

专业控制台、调用台、新手控制台里的参数（语速、种子、格式、语言、切句、`top_k`、本次选择的档案……）**只对当前这次合成或训练有效**，不会写回设置，也不会影响下一次请求。

档案 `meta.json` 里的值介于两者之间：它是**档案级默认值**。请求里显式给出的字段优先于档案值，档案值又优先于全局默认档案。

### 7.3 源码 / 服务形态的环境变量

没有桌面壳时，用环境变量达到同样的「全局默认」效果：

```powershell
$env:ADR_DATA_DIR = "D:\ADR_data"
$env:ADR_TTS_DEFAULT_PROFILE = "my_voice"
$env:ADR_TTS_DEVICE = "cpu"            # auto / cuda / cpu
$env:ADR_TTS_API_KEY = "key-a,key-b"
$env:ADR_LOG_LEVEL = "DEBUG"
python -m adr.server -p 9881
```

## 8. 数据目录、备份与迁移

### 8.1 数据到底存在哪

优先级从高到低：

1. 环境变量 `ADR_DATA_DIR`
2. `F:/ADR_data`（旧版遗留路径，存在即沿用）
3. `%LOCALAPPDATA%\ADR\data`（Windows 默认）

数据目录里通常有：

```
data/voices/        音色档案（ref.wav + meta.json + 可选权重）
output/uploads/     控制台上传的原始录音
output/             训练产物与日志
logs/server.log     服务日志
tts_cache/          合成缓存
.local_account      本机账号（仅桌面版）
```

**预训练底模不在数据目录**，它在安装目录的模型目录里，由预热流程下载和管理；可以在首启向导第 3 页查看位置、检查完整性或打开目录。

### 8.2 三种备份方式

| 方式 | 带走什么 | 适合 |
| --- | --- | --- |
| 导出 `.adrvoice` 音色包 | 单个档案的参考音频 + 权重 + 元数据 | 换电脑、分享给自己的另一台机器 |
| 复制整个数据目录 | 全部档案、上传、日志、缓存、账号 | 完整迁移或整机备份 |
| 只复制 `data/voices/` | 所有音色档案 | 只要声音、不要日志和缓存 |

复制数据目录前先**退出 ADR**，避免训练或合成正在写文件。

### 8.3 迁移到新电脑

1. 新机器安装同版本（CPU / GPU 包按新机器选）。
2. 启动一次，完成条款、账号和预热，让目录结构生成。
3. 退出 ADR，把旧机器的 `data/voices/` 复制到新机器的数据目录；或在新机器用「导入音色包」逐个导入 `.adrvoice`。
4. 重新启动。档案会在声音列表和 `/api/adr/v1/profiles` 里出现。

注意：

- 升级 / 重装不会删除数据目录里的声音档案。
- 在设置里改「存放目录」**不会自动迁移**旧目录的档案，需要手动复制。
- 权重文件和参考音频要一起迁移，只拷 `meta.json` 不够。

## 9. 文档中心

- 入口：各控制台右上角「文档」，或索引页的「文档中心」卡片。
- 内容：内置全部用户文档，离线可读；联网时可以「检查更新」比对官方仓库。
- 语言：有英文版本的文档可以切到 English；没有英文版本的会**回落到中文原文并明确提示**，不会报错。
- 搜索：支持模糊搜索和口语化说法（例如「没声音」「装不上」「爆显存」「401」），会直接定位到对应文档。
- 安装包漏拷 `docs/` 时，文档中心会明确提示「本机安装包未包含文档」，而不是假装已是最新。

## 10. 一句话流程

**装好 → 登录 → 新手控制台建声音 → 专业控制台训练并绑定 → 合成试听 → 需要接别的软件就去调用台 → 定期导出音色包备份。**

遇到问题先看 [故障排查](troubleshooting.md)。
