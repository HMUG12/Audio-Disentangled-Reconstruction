# 故障排查

每条按 **现象 → 原因 → 处理** 写。先做三件通用的事，往往能直接定位：

1. 打开 **专业控制台 → 总览**，点「一键诊断」；有可修项时会出现「自动修复问题项」。
2. 看数据目录下的 `logs/server.log` 尾部，以及专业控制台的训练 / 合成日志。
3. 访问 `http://127.0.0.1:9881/api/adr/v1/health`，确认 `engine_ready`、`engine_stage`、`engine_error`。

> 提 Issue 时请附上：ADR 版本、安装包类型（CPU / GPU）、Windows 版本、显卡型号、`server.log` 尾部 50 行、诊断报告。不要在公开 Issue 里贴 API Key 或私人音频。

---

## 1. 安装失败 / 被杀软拦截

**现象**

- 双击安装包没反应，或弹出「Windows 已保护你的电脑」。
- 360、火绒、Defender 报毒并删除安装包 / `adr-desktop.exe` / `runtime` 里的文件。
- 安装到一半失败，提示没有权限或路径过长。

**原因**

- 安装包没有商业代码签名，SmartScreen 会按「未知发布者」拦截；杀软对打包的 Python 运行时和 Tauri 壳容易误报。
- 安装是 per-user 的，不需要管理员权限；但装到 `Program Files` 等受保护目录、或安全软件锁定目录时会失败。
- 极长路径或磁盘空间不足。

**处理**

1. 在 Release 页面核对安装包的 SHA256 是否一致；不一致说明下载损坏，重新下载。
2. SmartScreen：点「更多信息 → 仍要运行」。
3. 杀软：把安装包和安装目录（默认 `%LOCALAPPDATA%\Programs\ADR Studio`）加入信任 / 排除项，再重装。不要直接关闭系统防护长期裸奔。
4. 换一个普通目录安装，或使用静默安装指定目录：

   ```powershell
   .\ADR-Studio-*-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR="D:\ADR Studio"
   ```

5. 确认磁盘剩余空间足够（CPU 版约 2GB、GPU 版约 4GB，不含底模和声音档案）。
6. 仍失败时，在安装日志和 `%TEMP%` 里找 Inno Setup 的错误行；提 Issue 时一并附上。

## 2. 引擎一直加载 / 卡在预热页

**现象**

- 预热页进度长时间不动，或一直显示「正在加载引擎」。
- 启动器能进，但合成一直排队，`/api/adr/v1/health` 的 `engine_stage` 停在 `importing` / `loading` / `kernel`。
- 日志里出现 numba 缓存、CUDA 初始化或 watchdog 相关信息。

**原因**

- 第一次启动要下载约 2GB 预训练底模，网络慢或下载源不通。
- 底模不完整或模型目录被移动。
- numba 缓存落在只读 / 无权限路径。
- 显卡驱动异常，CUDA 初始化反复重试。
- 13 / 14 代 Intel CPU 的兼容性问题导致计算阶段闪退。

**处理**

1. 等：首次预热包含下载 + 引擎加载，慢是正常的；预热页会显示阶段和进度。
2. 网络：在「启动器 → 设置 → 模型下载源」切到 **hf-mirror（国内）**，或设置下载限速避免把带宽打满；保存后重启引擎。
3. 模型完整性：首启向导第 3 页或设置里点「检查完整性」，缺失的部分会在下次预热补齐。
4. numba：在「设置 → 高级设置 → NUMBA 缓存目录」指定一个可写目录（如 `D:\adr_numba_cache`），再启动。
5. 设备：把「推理设备」临时改成 `cpu`。若 CPU 能起来，问题集中在 CUDA / 驱动。
6. 13 / 14 代 Intel：勾选「CPU 兼容模式」，性能略降但能规避闪退。
7. 看 `logs/server.log` 最后 50 行；`engine_error` 字段通常会给出失败阶段的原因摘要。
8. 仍卡死时退出 ADR（托盘 → 退出）后重启；进程级看门狗会在永久降级时重启引擎。

## 3. CUDA 不可用 / 显存不足（OOM）

**现象**

- 总览显示 CPU，日志提示回退 CPU。
- 训练一开始就失败，报 `CUDA out of memory` / `OOM` / `Allocation on device`。
- 合成到一半 503，错误信息里有显存相关字样。
- `nvidia-smi` 能看到显卡，但 ADR 不用。

**原因**

- 装的是 **CPU 版安装包**，本身不含 CUDA 运行时。
- NVIDIA 驱动过旧，或显卡不在 CUDA 支持范围内。
- 显卡被游戏、浏览器硬件加速、另一个 GPT-SoVITS 服务占满。
- 8GB 配方对 4GB 卡来说太大；或者参考音频 / 文本过长。
- 设置了过低的 `ADR_GPU_MEM_FRACTION`。

**处理**

1. 确认包型：安装目录下 `runtime\BUILD_VARIANT.txt` 应为 `gpu`；不是就换 GPU 版安装包。
2. 驱动：`nvidia-smi` 能正常输出且 CUDA Version 不太旧；必要时更新 NVIDIA 驱动。
3. 关掉其它占卡程序，再试。
4. 训练改用 **4GB 配方**（batch 1、单段 ≤10 秒），或减少训练轮数。
5. 推理：设置里把设备改成 `auto` 或 `cpu`；CPU 能跑，只是慢。
6. 显存上限：如果首启向导或环境变量设了 `ADR_GPU_MEM_FRACTION`，先取消或调高；它达到上限会主动抛 OOM，而不是拖垮整机。
7. 长文本：拆成短句，或调整切句方式（`cut3` / `cut5`）。
8. 没有 NVIDIA 卡：本机只能 CPU 推理；训练请用 NVIDIA 机器或云 GPU，训完导出 `.adrvoice` 拷回。

## 4. 合成没声音

**现象**

- 请求成功（200），但播放器没有声音，或音频是空的 / 极短。
- 新手控制台点「生成语音」后一直转圈，最后提示失败。
- 调用方拿到 0 字节或无法解码的文件。

**原因**

- 文本为空、只有空白或只有标点。
- 音色档案不存在、`ref.wav` 损坏、没有可用权重。
- 第一次合成还在冷启动，请求超时。
- 选错输出格式：`raw` 是裸 PCM，普通播放器不能直接当 WAV 播。
- 浏览器自动播放策略拦截，或系统音量 / 输出设备不对。
- 服务端返回了 401 / 500 / 503，客户端把错误响应当成音频保存。

**处理**

1. 换一句正常中文文本测试，排除文本问题。
2. 专业控制台刷新档案列表，确认档案存在；试听档案参考音频是否正常。
3. 看 `/api/adr/v1/health`：`engine_ready` 为 false 时先等预热完成。
4. 格式改回 `wav` 再试；确认下载下来的文件头是 `RIFF`。
5. 检查音量、输出设备、浏览器是否静音；点一下页面再用播放按钮（绕过自动播放限制）。
6. 用调用台发一次请求，看 HTTP 状态和错误 JSON；401 看第 7 节，500 / 503 看 `server.log`。
7. 如果是某个档案一直没声音，换一个档案对比：能出声说明问题在该档案的参考音频或权重。

## 5. 训练中断 / 训练失败

**现象**

- 训练状态从「运行中」变成「失败」或「已停止」。
- 日志最后一行是 OOM、`Killed`、文件不存在、超时或 traceback。
- 点「开始训练」提示「已有训练在进行」。
- 训练完成但相似度没有提升，或音色反而变差。

**原因**

- 显存不足，或同时跑了两轮训练（409）。
- 录音太短、全是静音、多人说话、背景音乐太重。
- 磁盘空间不足，或输出目录不可写。
- 训练脚本缺失（安装包不完整，常见于只拷贝了部分目录）。
- 训练超时（`ADR_TRAIN_TIMEOUT`）或用户点了停止。
- 轮数过多导致过拟合；质量门禁被关闭。

**处理**

1. 先点「■ 停止」，等旧进程真正退出，再重新开始；不要连续快速点两次。
2. 换 4GB 配方、降低轮数，关闭其它占卡程序。
3. 换一段 1 分钟以上、干净、单人的录音；确认能正常试听。
4. 检查磁盘剩余空间和输出目录权限。
5. 确认安装目录里存在 `scripts/gsv_finetune.py`；缺失就重装完整包。
6. 保持「质量门禁」开启（相似度 ≥ 0.80 自动早停），不要盲目堆轮数。
7. 训练失败不会破坏已有档案；修好后可以重新训练或从上一版权重回滚。
8. 把训练日志尾部贴进 Issue，里面通常直接写了失败阶段。

## 6. 模型 / 音色档案「不见了」

**现象**

- 声音列表空了，或某个档案消失。
- 设置里的「默认声音档案」报不存在。
- 调用返回 `profile not found`。
- 模型库显示未下载，但之前明明下载过。

**原因**

- 数据目录变了：设置了 `ADR_DATA_DIR`、改了「存放目录」，或旧版 `F:/ADR_data` 不再存在。
- 在资源管理器里重命名 / 移动了 `data/voices/<name>` 目录，但 `meta.json` 没跟着改。
- `meta.json` 损坏、编码错误，或权重文件被单独删除。
- 模型目录在安装目录下，重装到不同位置后旧模型不会被带过来。
- 启动时用了另一个 Windows 用户，`%LOCALAPPDATA%` 不是同一个。

**处理**

1. 在设置里看「当前生效」的数据目录路径；确认档案实际在哪个目录。
2. 用「打开」按钮直接打开该目录，检查 `data/voices/` 下是否还有你的档案。
3. 如果换过目录：把旧目录的 `data/voices/` 复制回来，或重新指定 `ADR_DATA_DIR`。
4. 目录名必须和 `meta.json` 内的档案名一致；手工改名后要同步修改元数据，否则会加载失败。
5. `meta.json` 损坏时，从备份恢复；没有备份就重新导入 `.adrvoice`，或重建档案。
6. 模型缺失：在首启向导 / 设置里点「检查完整性」，让预热重新补齐；或手动把权重按 GPT-SoVITS 目录结构放回模型目录。
7. 确认没有多个 ADR 进程同时使用不同数据目录。

## 7. 401 / 413 / 429

### 401 Unauthorized

**现象**：接口返回 `401 unauthorized`，控制台提示未授权。

**原因**：服务设置了 `ADR_TTS_API_KEY`，但请求没带凭据、凭据不对，或用了已关闭的 `?api_key=` 查询参数。

**处理**：

- 三种凭据任选其一：`Authorization: Bearer <key>`、`X-API-Key: <key>`、`?api_key=<key>`（查询参数默认关闭）。
- 如果客户端只能拼 URL，显式开启查询参数鉴权：`ADR_ALLOW_QUERY_API_KEY=1`，并接受它残留在日志 / 历史里的风险。
- 确认 key 精确匹配（大小写敏感），多把 key 用逗号分隔。
- `GET /api/adr/v1/health` 免鉴权，可以用它先确认服务活着。

### 413 Payload Too Large

**现象**：返回 413，或上传 / 导入档案包失败。

**原因**：非 multipart 请求体超过 `ADR_MAX_BODY_MB`（默认 16MB）；文本超过上限；档案包超过导入上限；单篇文档超过 800KB。

**处理**：

- 缩短文本，或分批合成。
- 调大 `ADR_MAX_BODY_MB`（服务端）与 `ADR_PROFILE_IMPORT_MAX_MB`（档案包导入）后重启服务。
- 文档 413 说明该文件超过文档中心的 800KB 上限，属于保护行为，不是故障。

### 429 Too Many Requests

**现象**：返回 429。

**原因**：**ADR 当前版本不会主动返回 429**。出现 429 基本可以确定是前面的反向代理 / 网关 / CDN 在限流（Nginx、Cloudflare、公司网关等）。

**处理**：

- 看代理的限流配置和响应头（`Retry-After`、`X-RateLimit-*`）。
- ADR 自己的过载信号是 **503 `busy: synthesis queue full`**，不是 429；遇到 503 应降低并发或稍后重试，不要当参数错误反复重试。

## 8. 端口被占用

**现象**

- 启动横幅提示 9881 被占用，或桌面端给出另一个可用端口。
- `OSError: [WinError 10048] 通常每个套接字地址只允许使用一次`。
- 浏览器打开 `127.0.0.1:9881` 是别的服务页面。

**原因**：另一个 GPT-SoVITS / TTS 服务、旧 ADR 进程或别的程序占用了 9881。

**处理**：

1. 查占用：

   ```powershell
   netstat -ano | findstr :9881
   tasklist /FI "PID eq <上一步的PID>"
   ```

2. 是旧 ADR：从托盘退出，或结束残留的 python 进程。
3. 是别的 GSV 服务：要么停掉它，要么给 ADR 换端口：

   ```powershell
   python -m adr.server -p 9882
   ```

   桌面版在设置 → 高级 → 服务端口里改（`0` 表示默认 9881，被占自动回退），保存后重启引擎。
4. 换端口后，N.E.K.O 和调用方地址要同步改。
5. 局域网访问不了：确认监听 `0.0.0.0`、Windows 防火墙放行该端口、并设置了 API Key。

## 9. 文档打不开 / 文档中心是空的

**现象**

- 点「文档」抽屉一直转圈，或提示「文档接口不可用」。
- 提示「安装包内未找到文档」。
- 某篇文档 404 / 502 / 413。
- 直接双击 HTML 文件打开时文档是空的。

**原因**

- 文档接口是同源的 `/api/adr/v1/docs`，必须由 ADR 服务页面打开；`file://` 直接打开没有后端。
- 安装包漏拷 `docs/`，或只拷贝了部分文档。
- 选了「在线」来源但网络不通 / 官方仓库路径不存在。
- 单篇文档超过 800KB，被主动拒绝。
- 桌面壳的预热页 / 加载页本身不启用文档抽屉。

**处理**

1. 确认是通过 `http://127.0.0.1:9881/`（或桌面壳）打开控制台，而不是本地文件。
2. 文档中心提示「未包含文档」时，重装完整安装包；不要只覆盖 `adr/` 目录。
3. 切回「本地」来源；在线来源失败会降级为本地结果，不会阻塞控制台。
4. 404 表示该 slug 不在白名单或官方仓库暂无该篇；不是所有内部文档都会对外提供。
5. 502 是官方仓库不可达（离线、代理、DNS），本地文档仍可读。
6. 语言：没有英文版本的文档会回落到中文并显示提示，这是预期行为。

## 10. 切换语言 / 主题异常

**现象**

- 点了「EN / 中文」没反应，或只切换了一半（按钮变了、正文没变）。
- 主题切换后颜色错乱、文字看不清。
- 刷新后又变回旧语言 / 旧主题。

**原因**

- 浏览器 LocalStorage 被禁用、写满，或存了非法值。
- 页面脚本被 CSP / 插件 / 翻译插件拦截或改写。
- 浏览器自带的整页翻译和 ADR 的 i18n 同时生效，出现中英混排。
- 桌面壳 WebView 缓存了旧页面。

**处理**

1. 再点一次切换按钮，或强制刷新（`Ctrl + F5`）。
2. 语言偏好存在 `localStorage` 的 `adr_lang`，主题存在 `adr.theme`。在浏览器开发者工具 → Application → Local Storage 里删除这两个键，再刷新。
3. 关闭浏览器整页翻译插件 / 翻译功能后再试。
4. 确认没有禁用 JavaScript、没有拦截 `/i18n*.js`、`/theme.js`。
5. 桌面壳：从托盘完全退出后重启；仍异常时清理 WebView2 缓存再启动。
6. 主题只影响界面配色，不影响合成结果；切回「默认」即可恢复。

## 11. 还是不行？

按这个顺序收集信息，能覆盖 90% 的问题：

1. 专业控制台 → 总览 → 「一键诊断」→ 复制诊断报告。
2. `logs/server.log` 尾部 50 行（**先确认没有 API Key、路径里的用户名等隐私**）。
3. `/api/adr/v1/health` 的完整 JSON。
4. 出问题的具体操作、时间点、能否稳定复现。
5. 安装包类型（CPU / GPU）、版本号、`runtime\BUILD_VARIANT.txt` 内容。

然后到 [GitHub Issues](https://github.com/HMUG12/Audio-Disentangled-Reconstruction/issues) 搜索是否已有同类问题；没有就新建，附上以上信息。
